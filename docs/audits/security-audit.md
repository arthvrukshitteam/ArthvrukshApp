# Security audit (static review — nothing exploited, nothing probed live)

Scope: `origin/version2` @ `8a0089a1` source only. No production access, no dependency scan, no dynamic testing. Severity = likelihood × impact for this app (financial-advisory tool handling client PAN/phone on a public, unauthenticated API). "Verified" = read in code.

| # | Sev | Finding | Evidence | Recommended fix |
|---|---|---|---|---|
| S1 | **High** | **Client PII is exposed without authentication.** `POST /api/proposal/build` stores `client_name`, `client_phone`, `client_pan` in plaintext in `portfolio_proposals`; `GET /api/proposal/{id}` and `…/export.{pdf,xlsx}` return them to anyone holding the ID; PAN also appears in the download filename (`_safe_filename`). IDs are unguessable (64-bit random) but never expire and are shareable. | `proposal_routes.py` L305-L357, L374 | Add auth; encrypt/mask PAN at rest; store only last-4; expire proposals; drop PAN from filenames; consider whether PAN is needed at all. |
| S2 | **High** | **SSRF + unauthenticated fetch-and-store.** `POST /api/overlap/ingest {urls}` makes the server `GET` arbitrary URLs (`follow_redirects=True`, 40 MB cap, 120 s timeout) with no allow-list and no auth; failure text (`str(exc)[:300]`) is returned to the caller, giving an error oracle for internal hosts/ports. `/ingest-upload` accepts 40 MB base64 bodies without auth. `AMC_SOURCES` allow-list exists but is empty and unused as a restriction. | `overlap_routes.py` L136-L165; `holdings_ingest.fetch_workbook` | Gate behind operator auth; allow-list schemes/hosts (AMFI/AMC domains); block private/link-local IP ranges after DNS resolution and after redirects; return generic errors. |

## IDOR / authorization summary
No object-level authorization exists at all (see [authentication.md](../architecture/authentication.md)). Treat every ID-addressed resource (`/proposal/{id}`, `/rolling-analysis/{id}`, `/rank/{id}`, `/bulk-analysis/{job_id}`) as public-by-link.

## Compliance-adjacent observations (not legal advice)
* Exports print a hard-coded legal entity name and ARN default (`ArthVruksh MFDGuru LLP`, `365554`), and the client duplicates the entity name in `RECOMMENDED_BY`. Changing either affects regulated documents.
* The UI/PDFs present scores and "Remarks" such as "Bad — Should Discontinue" (`get_fund_remark`, FQS<75). Whether the required disclaimers/risk statements are present in PDFs was **not** reviewed (UNKNOWN).
* Backtest evidence committed in the repo explicitly states the validation is statistically uninterpretable on the fixture (≈2 independent periods) — do not cite it as proof of predictive power in client material.
